# Security Policy

## Supported Versions

Security fixes are made on the `main` branch. The deployed site is rebuilt from
that branch, so use the latest published version when reporting an issue.

## Reporting a Vulnerability

Do not open a public issue for a suspected vulnerability. Instead, contact the
repository owner through the contact method shown on the GitHub profile for
[`ninjapaw`](https://github.com/ninjapaw), including:

- A clear description of the potential impact.
- Steps to reproduce the issue.
- Any proof-of-concept or relevant request/response details.

Do not include credentials, access tokens, tenant data, or other sensitive
information in a report. Reports are reviewed privately; please allow time for
triage before disclosing details publicly.

## Scope

This repository is a static site. Security reports are most useful when they
relate to source code, build and deployment configuration, dependencies, or
the deployed site. Microsoft 365 licensing questions and product entitlement
concerns should be directed to the appropriate Microsoft support channel.
